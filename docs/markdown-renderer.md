# Markdown rendering

Use `MarkdownRenderer` for chat replies, file previews, plans, pull requests and changelog content. It uses `react-native-enriched-markdown` on iOS, Android and web. Keep source adaptation and renderer configuration in `components/markdown`; consumers supply Markdown and, when needed, its file location.

Native selection belongs to the library's text view. Keep an assistant message in one row so selection can cross paragraphs, headings and lists. Code blocks and tables use the library's native views and their selection behavior. Web uses browser selection over semantic HTML. Once its WASM parser is initialized, the library parses synchronously for the first commit of each mounted row; an empty interim row would corrupt virtualized measurements and move the reader. Chat owns paced reveal, the web render cap, message identity and list measurement. Native renders completed messages together. While streaming, it keeps closed blocks in one head view and updates a separate tail, then reunites the text on completion. See [native parsing cost](agent-stream-performance.md#native-parsing-cost) for the boundary and pacing constraints.

## Block spacing

Every block is separated by one gap, `density.blockGap`: 12 on compact layouts, 16 wider. Inside the library's text, every element style ends with that gap and the library drops it after the last block. Views stacked outside the library (Mermaid segments, streaming head and tail) use the same gap through `MarkdownBlockStack`. Do not give a block type its own margins; change the gap.

## Links and images

Workspace file links use the shared file-link resolver. The workspace supplies its client, root and open-file action once; chat can supply the agent's more specific context. URLs use the same link press path. Recognized inline-code paths stay tappable. The library callback carries the tapped occurrence’s syntax context. Preserve it when opening files: explicit Markdown links decode URL escapes, while recognized inline-code paths preserve literal percent characters and use suffix lookup. Identical URL strings in different occurrences must stay distinct. Explicit absolute workspace links receive a relative hover title; existing authored titles remain intact. Inside a workspace, forge references such as `#12` and `owner/repo#12` are recognized in prose (not code) and open the workspace forge; the reference pattern comes before path recognition so `group/project#12` is not read as a path. See [forge providers](forge-providers.md#gotchas).

A bare file name or relative path in chat is looked up through a ladder in `packages/app/src/assistant-file-links/ladder.ts`. The first step with a hit answers; later steps never run.

1. The agent's own tool calls in the loaded timeline (`tool-call-paths.ts`): files it read, wrote, edited or searched, matched by whole path segments. No daemon call, and it finds output in git-ignored or outside-cwd folders because the agent just touched it.
2. A suffix search in the agent's cwd, then the same search with `includeIgnored`. The ignored pass skips dependency folders (`node_modules`, `venv`, `.git`) but walks `out`, `dist` and `build`, and stops at a fixed entry cap. It runs only on hosts with `server_info.features.directorySuggestionsIncludeIgnored`; older hosts skip it.
3. The same two passes from the workspace folder, then the project root, when they differ from the cwd.

More than one match at the winning step opens a "which file?" sheet (`file-link-chooser.tsx`, an `AdaptiveModalSheet`, so it is a bottom sheet on a phone). One match opens directly. Dismissing the sheet opens nothing and shows no toast; "No file found" shows only when the whole ladder misses. The context menu and offline save use the same ladder through `resolveFileLinkLookup`. Absolute and `~` paths on another host keep their separate probe (`host-pick.ts`). Only the daemon steps are cached; the tool-call step is read fresh so a growing timeline is seen.

Pass `external` for author-controlled Markdown from outside the host, such as a plugin README. It follows the registry's overview contract in `packages/protocol/src/plugin-overview.ts`, which the website also uses: only absolute https links and images work, and any other destination renders as its label or alt text. The parser still autolinks bare `http://`, `www.` and email text, so a link press checks the URL again and opens only https. None of the workspace recognition above applies, so `Node.js` is prose, not a file. The lines of a paragraph join, as they do on the README's forge.

Resolve workspace image paths over the existing session RPC, then give the library a cached native file URL or web blob URL. HTTP(S) images pass through unchanged. This preserves relay, SSH and local socket connections, which do not expose a daemon HTTP endpoint. Each mounted renderer owns its image acquisition identity, so a later reply reads a rewritten path again while the earlier mounted reply retains its snapshot. Image taps open the attachment lightbox. File previews resolve relative images against the Markdown file's directory. An image alone on its line becomes its own paragraph before the library sees it, so it renders as a block on every platform; the library only treats sole-child paragraph images as blocks, and with hard soft breaks every newline is a break node, which left own-line images inline on iOS and web. Images that share a line with text stay inline at line height and keep their aspect ratio. A linked image counts as an image, so review-bot badges such as `[![Retrigger](badge.svg)](url) Confidence` stay inline on web; the library's web renderer only checked direct paragraph children, so it rendered them as full-width block images (local patch in `patches/react-native-enriched-markdown+*.patch`).

## Engine constraints

The pinned nightly has the same React Native package and core source trees as upstream commit `73ac5085eb1fdc743973b3473d4dba65abad5261`. Compatibility was checked with React Native 0.81.5. Native dependencies must be rebuilt when changing the highlighting configuration; JavaScript refresh cannot enable compiled grammars.

Math and video are disabled. Task lists and admonitions are enabled; task checkboxes are read-only. Source adaptation spaces adjacent empty GFM table delimiters before escaping prose spoiler delimiters and decodes entity text before the engine can discard it. Code spans and fences keep their literal source, with one exception: a closed fence whose every line is a file path (at most 20) becomes inline code, one path per line. Agents often put a lone path in a fence, and the library never recognizes links inside a code block, so the path would not open. Lines that are quoted, backticked or carry anything besides the path keep the fence. `packages/app/src/components/markdown/file-mentions.test.ts` lists every way an agent names a file and what each opens.

Mermaid fences use the existing isolated diagram runtime and fullscreen viewer. Web dispatches them through the library’s code-block override. Native has no block-renderer hook, so the renderer extracts Mermaid fences and places the existing WebView host between library-rendered segments (`components/markdown/fence/segments.ts`). Streaming keeps the last valid diagram visible while the next revision renders.

Shell fences (`bash`, `sh`, `shell`, `zsh`, `console`) in an agent's chat get a Run control: an icon beside Copy on hover layouts, a labeled 44pt button under the block on touch layouts. Untagged fences get one too when every line starts like a command (`code-run/detect.ts`); agents often leave the tag off one-liners. Keep that detector strict: a Run button on output, code or prose is worse than a missing one, so it also rejects lone paths, brace-heavy blocks, sentences and anything over 20 lines. Other languages never run. The chat marks a message as runnable with `CodeRunScopeProvider` (`code-run/scope.tsx`); file previews and read-only transcripts don't, so their fences stay plain code and stay inside the native text view. In a runnable message, native extracts runnable fences the same way as Mermaid fences and renders them with `HighlightedCodeBlock`. Mermaid and runnable shell fences are the only block exceptions; see [native selection limitations](native-text-selection.md) for what extraction costs.

Run opens an inline card under the fence that names the host and folder and needs a second tap to start; commands with `sudo`/`doas` or `rm -rf` carry a warning label but no extra tap. The card runs the command in a new terminal in the agent's workspace, the way a person would type it into a shell. It wraps the block in a `{ }` group so a command reading stdin cannot swallow the rest, and prints start and exit lines stamped with the host's clock, so a card that reattaches later reads the status and duration from the captured screen. That wrapper assumes a POSIX shell; fish and Windows shells are not supported. Re-run types the command again into the same terminal under a new nonce. The card subscribes to the terminal only while it is mounted, its panel is active, and the app is visible, stops once the status line appears, and runs no animation loops. Typed answers go straight to the terminal and are never stored or shown; the answer field switches to masked entry when the last output line asks for a password, and `[y/N]`-style prompts get Yes/No/Enter chips. On native the focused answer field rides the keyboard with the chat (`keyboard/shift`); on web it scrolls itself into view. The device remembers which terminal each fence ran in (`code-run/store.ts`), never the output.

A fence can name where it runs after its language: ` ```bash host=macbookpro cwd=~/src `. `host=` is one of your hosts by label (case and spaces ignored) or serverId, and `cwd=` defaults to that host's home. A terminal must belong to a workspace, so the run joins the deepest open workspace on that host that holds the folder, hidden ones included; when none does, Run first opens a hidden (background) workspace there, which gets no sidebar row and is reused by later runs (`code-run/target.ts`, `code-run/workspace.ts`). An unknown or offline host gets a message and no Run, and a workspace the host refuses to open shows its reason on the card; the card never falls back to the chat's host. The web engine passes code blocks only the first info word, so web splits tagged fences out of the engine the way native does.

Other native code blocks use the library's copy control and compiled grammars. Web code blocks use `HighlightedCodeBlock` through the library's `renderers.codeBlock` override. The patch also keeps the library's block spacing around the web code block override, preserves web list numbering and link titles, marks pending parses with `aria-busy` so Find waits for rendered text, and carries link syntax through native and web tap events. Web inline code inside a link inherits only the link colour; its code font, size and background stay intact. Keep link variants colour-only: native pills replace text runs and prevent paths from wrapping; Android pills also use the surrounding block’s font size. The package patch is tracked by [upstream PR #997](https://github.com/software-mansion/enriched-markdown/pull/997); remove the patch when the pinned release includes it.

The package patch also keeps overflowing native horizontal blocks in control of their drags: Android claims parent interception at touch-down and releases it for vertical drags so the chat list can scroll; iOS keeps its scroll recognizer active for outward drags at the leading edge. This prevents compact sidebar pans from taking block scrolling without changing sidebar swipes on prose or non-overflowing blocks. Native changes require a client rebuild.

On iOS a newly mounted Markdown view paints empty for a frame or more after it is laid out at its measured height: the library parses even a view's first content on a background queue and applies it in a later main-queue turn. Expanding a turn in chat therefore shows its rows in place with the text arriving a frame later (165 ms when the mount keeps the main thread busy). Android paints the text in the first frame. Rendering a view's first content synchronously fixes the frame but costs frame time when a fling mounts history rows, so the app keeps the library's behavior until [enriched-markdown #1131](https://github.com/software-mansion/enriched-markdown/issues/1131) is resolved.

Android measurements use a size-only, 512-entry LRU across view unmounts, matching the library’s existing iOS cache. Scrolling back through history can reuse layout sizes without parsing those rows again. Content, layout props and width identify each entry; font-scale changes and native layout invalidation discard affected sizes. The cache retains no views or spans.

The library determines how incomplete Markdown appears during streaming. Completed text uses the same component and engine as history. Find and scroll-to-message address source message ids; selection-copy understands semantic HTML and the web code component's copy metadata.
