# Brief: daemon-owned message queue

Branch: `feat/daemon-message-queue` (worktree `~/git/paseo-daemon-message-queue`, based on `upstream/main`).
Fork workflow: see `CLAUDE.md` → "Fork workflow". One concern per branch. Open a draft PR on `Khang5687/paseo` after the first commit; delete this file before the PR leaves draft.

## Bug

Queue a message on desktop while the agent runs → open the same agent on the phone → the phone shows no queued message, and if the phone is the client watching when the turn ends, nothing is sent. Reverse direction is the same.

## Why

The queue is client-local. `packages/app/src/stores/session-store.ts:433` keeps `queuedMessages: Map<agentId, {id,text,attachments}[]>` per connected server, and `host-runtime.ts:2392 drainQueuedAgentMessage` sends `queue[0]` via `send_agent_message` when that client sees the agent go idle (`timeline/viewed-timeline-sync.ts:252`). The daemon never knows a queue exists. Nothing in `packages/protocol` mentions queued messages.

## Target

The daemon owns the queue per agent; every client renders and controls the same list.

- **Protocol** (`packages/protocol/src/messages.ts`): new RPCs per `docs/rpc-namespacing.md`, e.g. `agent.queue.add.request/response`, `agent.queue.remove.*`, `agent.queue.update.*` (edit text), `agent.queue.send_now.*`. Push state as an optional field on existing agent snapshot/update messages or a new `agent.queue.updated` event — all new fields optional, never required (`docs/protocol-compatibility.md`). Gate the feature on `server_info.features.messageQueue` with a `// COMPAT(messageQueue): added in vX, remove after <date>` tag; when the host lacks it, keep the current client-local behavior (that _is_ the fallback the compat doc allows: old daemon, new app).
- **Server** (`packages/server/src/server/agent/agent-manager.ts`): store the queue on the agent record (`docs/data-model.md` — Zod schema, persisted with the agent so it survives daemon restart). When a turn ends (where `turn_ended`/idle is emitted), pop the head and dispatch it through the same path `send_agent_message` uses. Images/attachments: queued items carry already-encoded payloads so the daemon can replay without the originating client.
- **App**: `composer/index.tsx` reads `queuedMessages` from the store; keep that selector but feed it from the daemon push when the feature is on. `renderQueueTrack` / `QueuedMessageRow` edit + send-now call the RPCs. Remove the client-side drain when the host owns the queue.
- **Tests**: server test for queue persistence + auto-dispatch on turn end (`docs/testing.md`, real daemon harness in `docs/ad-hoc-daemon-testing.md`); protocol wire-compat test; app test for feature-off fallback. Run only the files you touch.

## Verify

Two clients (web + Expo iOS sim, or two web tabs on the same daemon) against `npm run dev`: queue on A, see it on B, end the turn, message sent once, both clients clear. Also: old-app-vs-new-daemon parse check.

## Out of scope

OMP's internal `/follow-up` queue (`queuedMessageCount` in OMP `get_state`). Separate branch.
